EXECUTIVE SUMMARY

The Pet Care & Veterinary Services Clinical Management System is a production-ready enterprise desktop application developed in Java Swing, backed by a relational MySQL database. The system automates clinical processes for modern veterinary clinics, eliminating scheduling collisions, unifying fragmented patient and pet records, dynamically calculating medical treatment costs, and compiling clinical audit reports using JasperReports.

Adhering strictly to enterprise software engineering standards, the system implements:

  • Layered Model-View-Controller (MVC) Architecture: Clean separation between user interface, business services, and database persistence layers.
  • Gang of Four (GoF) Design Patterns: The Singleton Pattern for safe database connection pooling and the Data Access Object (DAO) Pattern for clean modular data persistence.
  • Role-Based Access Control (RBAC): Tailored navigation and authorization for Managers (full clinical, financial, and reporting access) and Customers (pet registration and appointment booking).
  • Two Complex Multi-Step Transactions: Cascading appointment booking with doctor schedule conflict detection, and clinical treatment diagnosis with real-time billing calculations.
  • Comprehensive Validation & Custom Exceptions: Strict regex data validation and custom domain exceptions (InvalidAppointmentException).
  • JasperReports Multi-Table Audit Engine: Advanced SQL JOIN querying four relational tables (appointments, customers, pets, treatments) with interactive viewing and PDF/CSV export.

CHAPTER 1: INTRODUCTION & DOMAIN ANALYSIS

1.1 Domain Background

Veterinary practice management requires coordinating multiple interconnected entities: pet owners, animal patients of diverse species, medical specialists, appointment schedules, surgical procedures, and itemized billing. Unlike traditional human clinics where the patient is the customer, veterinary healthcare operates on a guardian-dependent model where owner contact profiles, animal medical histories, and clinical treatments must be linked relationally.

1.2 Problem Statement

Manual and spreadsheet-based clinic tracking introduces severe operational inefficiencies:

  • Doctor Double Bookings: Simultaneous appointments scheduled for the same doctor at the same time slot, leading to long clinic wait times.
  • Fragmented Medical Records: Lack of historical linkage between customer contact updates, animal vaccination records, and historical clinical diagnoses.
  • Inaccurate Billing: Manual addition of medication charges and procedure costs resulting in invoice errors and financial discrepancies.
  • Lack of Real-time Audit Visibility: Clinic managers struggle to generate instant revenue reports filtered by pet species, payment statuses, or specific treatment dates.

1.3 Project Aims & Objectives

The objective of this project is to develop an enterprise-grade desktop software system fulfilling all coursework criteria:

  • Develop a modern Java Swing GUI using FlatLaf styling for clean user experience.
  • Enforce Role-Based Access Control separating administrative from client workflows.
  • Provide normalized MySQL data persistence using the DAO and Singleton design patterns.
  • Implement two transaction workflows with business logic validation.
  • Integrate JasperReports for comprehensive multi-table join reporting.
  • Deliver automated scripts to build executable JAR and native Windows EXE distribution packages.

CHAPTER 3: SYSTEM ARCHITECTURE & SOFTWARE DESIGN PATTERNS

3.1 Layered MVC Architecture

The application is partitioned into four distinct architectural tiers to ensure maintainability, testability, and separation of concerns:

1. Presentation Tier (com.petcare.view): Java Swing user interfaces and event handling.
2. Business Logic Tier (com.petcare.service): Business rule validation, calculations, and exception handling.
3. Data Access Tier (com.petcare.dao): Parametrized JDBC SQL execution and object mapping.
4. Domain Model Tier (com.petcare.model): POJO entity classes representing business objects.

3.2 Singleton Design Pattern

Database connectivity is managed through a thread-safe Singleton class (DatabaseConnection.java) to avoid connection exhaustion and ensure connection reuse:

public class DatabaseConnection {
    private static DatabaseConnection instance;
    private Connection connection;

    private DatabaseConnection() throws DatabaseException {
        try {
            Class.forName("com.mysql.cj.jdbc.Driver");
            this.connection = DriverManager.getConnection(URL, USER, PASSWORD);
        } catch (Exception e) {
            throw new DatabaseException("Failed to establish database connection.", e);
        }
    }

    public static synchronized DatabaseConnection getInstance() throws DatabaseException {
        if (instance == null || instance.getConnection().isClosed()) {
            instance = new DatabaseConnection();
        }
        return instance;
    }

    public Connection getConnection() {
        return connection;
    }
}

3.3 Custom Exception Handling

The project defines domain-specific checked exceptions rather than generic runtime errors:

  • InvalidAppointmentException: Raised when appointment business rules are broken (past date selection, doctor schedule conflict).
  • ValidationException: Raised during form input verification (invalid emails, malformed phone numbers, negative numbers).
  • DatabaseException: Encapsulates SQL and JDBC connection errors into safe user-facing diagnostic messages.

CHAPTER 4: RELATIONAL DATABASE DESIGN & SCHEMA

4.1 Database Normalization (3NF)

The database schema is fully normalized up to the Third Normal Form (3NF):

  • 1NF: All columns store atomic values, each table possesses a primary key, and repeating groups are eliminated.
  • 2NF: All non-key attributes depend fully on the primary key, eliminating partial functional dependencies.
  • 3NF: Transitive dependencies are removed. For instance, customer contact details are stored strictly in customers rather than duplicated in appointments.

5.2 Transaction 1: Appointment Scheduling with Conflict Detection

When booking an appointment, the system executes two levels of data integrity enforcement:

  • Cascading Dropdown Selection: Selecting an owner dynamically filters the pet dropdown to show only pets belonging to that customer.
  • Doctor Schedule Collision Prevention: The system verifies if the selected veterinarian is already booked for that date and time slot:
if (appointmentDAO.isDoctorDoubleBooked(doctor, date, time)) {
    throw new InvalidAppointmentException(
        "Dr. " + doctor + " already has an appointment scheduled on " + date + " at " + time + "."
    );
}

5.3 Transaction 2: Clinical Treatment & Dynamic Live Billing

Doctors record clinical findings, procedures, and prescribed medications for appointments. The interface attaches live listeners to fee fields, recalculating total amounts instantly:

KeyAdapter calcListener = new KeyAdapter() {
    @Override
    public void keyReleased(KeyEvent e) {
        calculateTotalLive(); // Total Bill = Medication Fee + Procedure Fee
    }
};
txtMedCost.addKeyListener(calcListener);
txtTreatCost.addKeyListener(calcListener);

Upon submission, the treatment record is created, invoice status is recorded, and the appointment status is updated to Completed.

CHAPTER 6: JASPERREPORTS ENTERPRISE REPORTING

6.1 Multi-Table SQL Join Requirement

The coursework specification requires at least one Jasper Report utilizing joins from more than two tables. The system exceeds this requirement by joining four relational tables:

SELECT 
    a.appointment_code, 
    a.appointment_date, 
    c.full_name AS customer_name, 
    c.phone AS customer_phone, 
    p.name AS pet_name, 
    p.species, 
    p.breed, 
    a.vet_doctor, 
    t.diagnosis, 
    t.procedure_details, 
    t.medication_cost, 
    t.treatment_cost, 
    t.total_amount, 
    t.status AS payment_status
FROM appointments a
JOIN customers c ON a.customer_id = c.id
JOIN pets p ON a.pet_id = p.id
JOIN treatments t ON t.appointment_id = a.id
ORDER BY a.appointment_date DESC;

6.2 Report Architecture & Export Features

  • Template Design: Authored in VeterinaryServiceReport.jrxml with landscape layout, clinic branding banner, column headers, and itemized records.
  • Automatic Revenue Aggregation: Computes the total sum of filtered revenue in the Summary band using JasperReports calculation variables ($V{TOTAL_REVENUE}).
  • Multi-Format Output: Generates interactive Swing report preview (JasperViewer), direct PDF export (JasperExportManager), and CSV data export.

CHAPTER 7: INPUT VALIDATION & SYSTEM SECURITY

Robust validation is implemented centrally in ValidationHelper.java:

  • Email Validation: Strict RFC-compliant regex pattern verifying domain and syntax.
  • Phone Validation: Regex validating 7 to 15 numeric digits with optional country calling code prefix (+).
  • Required Fields: Non-empty checks stripping whitespace to prevent blank submissions.
  • Numeric Constraints: Enforces positive integers for age and non-negative decimal currency for fees.

10.2 Top Anticipated Viva Voce Questions & Answers

Q1: Explain the architecture of your application.
"Our system follows the Model-View-Controller (MVC) and Layered Architecture pattern. The View layer (com.petcare.view) manages Swing UI components; the Service layer (com.petcare.service) coordinates business rules, calculations, and validations; the DAO layer (com.petcare.dao) executes SQL operations; and the Model layer (com.petcare.model) defines domain entity objects."
Q2: Where and why did you implement the Singleton pattern?
"We implemented the Singleton design pattern in DatabaseConnection.java. Instantiating database connections is computationally and network expensive. The Singleton pattern guarantees that a single, centralized connection instance is shared across all DAO operations, preventing socket exhaustion and connection leaks."
Q3: How does your Jasper Report satisfy the join requirements?
"The coursework requires joining more than two tables. Our Jasper Report joins four tables: appointments, customers, pets, and treatments. This provides a complete audit trail from the pet owner down to individual clinical procedure charges and payment status."
Q4: What custom exception did you implement?
"We created InvalidAppointmentException.java, a checked exception triggered when business logic rules are broken during appointment scheduling—such as attempting to book a past date or scheduling an appointment when the veterinarian is already double-booked."
Q5: How do you protect your database against SQL Injection?
"All database queries across our Data Access Objects (DAOs) strictly use parametrized PreparedStatement objects. User input parameters are passed via indexed placeholders (?), preventing user data from altering SQL execution logic."
